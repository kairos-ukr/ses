# K-Core · Сервер документів

Окремий міні-сервіс. Приймає файли з сайту, стискає їх, кладе в папку
об'єкта на Google Диску і у фоні відправляє в гілку об'єкта в Telegram.
Сайт ходить сюди через Cloudflare Worker `quiet-water-a1ad.kairosost38500.workers.dev`
— адреси в коді сайту міняти не треба, лише щоб Worker дивився на цей сервер.

## Що де лежить

| Файл | Що робить |
|---|---|
| `main.py` | сервер (FastAPI), усі ендпоінти. Його і запускати |
| `config.py` | **усі налаштування й ключі** — прописані прямо тут |
| `authorize.py` | одноразовий вхід у Google, видає `google_token.json` |
| `check.py` | перевірка: Supabase, Диск, бот — нічого не змінює |
| `drive.py`, `folders.py` | Google Диск: папки, завантаження, мініатюри |
| `telegram.py` | фонова черга відправки в Telegram |
| `optimize.py` | стискання фото, PDF, Word/Excel |
| `naming.py` | назви файлів і типи документів |
| `db.py` | Supabase |

`config.py` і `google_token.json` у `.gitignore` — репозиторій публічний,
а там токен бота й ключі Google. На сервер їх заливати обов'язково.

## Запуск з нуля

1. **База.** Supabase → SQL Editor → виконати `db/2026-10_drive_folders.sql`.
   (Без цього сервер теж працює, але щоразу шукає папку об'єкта на Диску.)
2. **Google.** На своєму комп'ютері в папці `doc-server`:
   ```
   pip install google-auth-oauthlib
   py authorize.py
   ```
   Увійти тим акаунтом, якому належить папка проєктів → «Дозволити».
   З'явиться `google_token.json`.
3. **Сервер.** Залити весь вміст `doc-server` (разом із `config.py` і
   `google_token.json`) на bot-hosting. Головний файл — `main.py`.
   Залежності з `requirements.txt` панель ставить сама. Python 3.9+.
   Порт береться з `SERVER_PORT`, який панель задає сама.
4. **Worker.** Якщо адреса чи порт сервера змінились — оновити їх у
   Cloudflare Worker `quiet-water-a1ad`.
5. **Перевірка.** Відкрити `https://quiet-water-a1ad.kairosost38500.workers.dev/health`
   — має бути `"status": "ok"`. На сервері можна запустити `python check.py`.

## Як працює завантаження

1. Сайт шле файли (`object_number`, `doc_type`, `files`, для етапів — `stage_key`).
2. Сервер знаходить папку об'єкта: пам'ять → таблиця `drive_folders` →
   стара папка на Диску з номером об'єкта в назві → нова папка
   «Назва об'єкта #1234». ID папки записується в базу.
3. Файли стискаються:
   - фото — до 2560 px по довшій стороні, JPEG; HEIC з iPhone → JPEG;
   - PDF від 3 МБ — перетискаються скани/фото всередині;
   - Word/Excel/PowerPoint від 2 МБ — перетискаються вставлені картинки;
   - решта — як є. Береться лише результат, який справді менший.
4. Назва: `Тип_ДД_ММ_Назва об'єкта_(N).ext`, напр.
   `Фотозвіт_14_10_Межиріч Саша, Загребля 48_(3).jpg`. N продовжує
   нумерацію за день.
5. Збереження на Диск (паралельно), доступ «усі, хто має посилання».
   Сайт отримує відповідь одразу після Диска.
6. **У фоні** — Telegram, у гілку об'єкта (`installation_messages.thread_id`):
   фото й відео — альбомами до 10 як медіа, документи — групами до 10,
   підпис під першим повідомленням, файли понад 49 МБ — посиланням.
   Якщо гілки ще немає (бот створює її протягом хвилини після появи
   об'єкта), сервер спробує ще тричі з паузою 2 хв. Збої — адміну в особисті.

Рахунки постачальників без об'єкта йдуть у папку
«Склад · Рахунки постачальників», у Telegram — ні.

**Ліди** (`object_number` = `lead-12`) — у папку «Ліди / Лід #12 Ім'я», у
Telegram — ні: гілки в ліда немає. Коли з ліда роблять об'єкт, сервер при
першому зверненні до файлів об'єкта (сайт звертається одразу після
«Створити об'єкт») переносить папку ліда в головну папку й перейменовує на
«Назва об'єкта #1234» — усі фото й документи ліда стають файлами об'єкта.
Тоді ж усі ці файли стають у чергу Telegram і йдуть у гілку об'єкта, щойно
бот її створить (підпис «📎 Файли з ліда»).
Лід, який уже став об'єктом, завантажує одразу в папку об'єкта. Сайт
показує файли лідів лише тоді, коли `/health` повертає `"features": ["leads"]`.

## Ендпоінти

| Метод | Шлях | Що |
|---|---|---|
| POST | `/upload/` | документи (вкладка «Документи», заміри даху) |
| POST | `/workflow/upload` | файли етапів, рахунки постачальників |
| GET | `/documents/{custom_id}` | список файлів об'єкта (з підпапками) |
| POST | `/delete` | `{file_id}` → у кошик Диска (30 днів можна повернути) |
| GET | `/thumb/{file_id}` | мініатюра, `?size=800` |
| GET | `/design/variants/{custom_id}` | 3D-варіанти |
| POST | `/design/select` | `{variant_id, installation_custom_id}` |
| GET | `/health` | стан сервера |

Необов'язкові поля завантаження: `uploaded_by` (хто — піде в підпис
Telegram), `comment`.

## Якщо щось не так

- **У лозі `invalid_grant`** — Google відкликав доступ: запустити
  `authorize.py` ще раз. Якщо так щотижня — у Google Cloud застосунок
  у режимі «Testing»: OAuth consent screen → **Publish app**.
- **«RLS не дав записати project_design_variants»** — поставити в
  `config.py` ключ `service_role` замість anon.
- **Файли на Диску є, а в Telegram немає** — `python check.py`: чи бот
  адмін у групі, чи група — форум. Деталі в `logs/server.log`.
- Вимкнути Telegram зовсім: `SEND_TO_TELEGRAM = False` у `config.py`.
